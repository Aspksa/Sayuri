# Sayuri 0.1 — облачная кицунэ-помощница

Единый проект: **FastAPI + SQLite + Cloud.ru Foundation Models + адаптивный веб-чат**. Собственная локальная модель **не используется**. Cloud.ru вызывается **только сервером**; API-ключ не передаётся браузеру или мобильному приложению.

## Windows
1. Установите Python 3.10+.
2. Запустите `Sayuri.bat`.
3. Откройте http://127.0.0.1:8765 — для локального Windows запуска сразу откроется **Личный кабинет Саюри без пароля**.
4. Для ответа модели заполните API-ключ Cloud.ru в **Личном кабинете → Cloud.ru** (поле «API-ключ Cloud.ru») и выберите ID наставника из списка моделей. Настройки сохраняются на компьютере в закрытом `.env`; перезапуск после сохранения ключа не требуется.
5. Данные по умолчанию хранятся в `data/` (вне Git); для постоянного пути укажите **SAYURI_DATA_DIR**.

**Cloud.ru API**: сервер ожидает OpenAI-совместимый endpoint `<CLOUD_RU_BASE_URL>/chat/completions` с Bearer API-ключом и полями `model`/`messages`. Уточните актуальные URL и идентификатор модели в своём кабинете Cloud.ru. Ключ никогда не записывайте в репозиторий.

## Состояние реализации
- Регистрация единственного владельца, авторизация, чаты, история, облачные ответы, сохранение явной памяти, отзывы, локальная загрузка документов (без автоматической индексации).
- 100 синтетических диалогов (540 сообщений), 400 реплик в 50 категориях и персона v2.0 из `config/persona/v2_parts/`. Образцы не подмешиваются в реальную историю пользователя.
- Мобильная основа Flutter в `mobile/` подключается к тому же API; для доступа с телефона нужен защищённый доступ к серверу (HTTPS), а не просто localhost.
- Добавлен ИИ-наставник: укажите `CLOUD_RU_TEACHER_MODEL` в `.env`, затем в личном кабинете откройте «Изучить текущий чат». Кандидаты фактов записываются в память только после нажатия «Запомнить»; можно отклонить каждое предложение. Есть просмотр датасета обратной связи (не обучение весов). Следующие задачи: векторный поиск/RAG, полноценная обработка документов, регулярное облачное дообучение LoRA с тестированием, уведомления и защищённый удалённый сервер. **Самообучение весов модели сейчас отсутствует**.
- Проверка обновлений GitHub Releases через `updater.py` при запуске: **без автоматической установки**.\n- Доступ к «Рабочим проектам» и «Домашним проектам» — только чтение в пределах каталога, явно заданного через `SAYURI_PROJECTS_DIR`.\n- `Sayuri.bat` запускает Windows-сервер. Запуск с USB-носителя возможен при наличии Python и прав на запись; переносимость файлов не означает доступность облака офлайн.

## Безопасность
Запускайте локально на `127.0.0.1`. Для удалённого сайта и приложения обязательно используйте reverse proxy с HTTPS, ограничения входа, управление устройствами, резервные копии и HTTPS до провайдера. Вложения не отправляются в Cloud.ru автоматически. БД и секреты не попадают в git. Не размещайте сервер напрямую в интернете без дополнительной защиты.

Проверка: `python -m compileall server run.py` и `pytest` после установки зависимостей.

## Cloud.ru
Официальная база URL: `https://foundation-models.api.cloud.ru/v1`.
Задайте `CLOUD_RU_MODEL` из списка моделей, доступных вашему сервисному аккаунту, и секрет в локальном `.env`.
Опционально `CLOUD_RU_TEACHER_MODEL` позволяет отдельно анализировать чаты и **предлагать** подтверждаемую память. Сведения не записываются наставником автоматически. В кабинете доступны оценки ответов и предпросмотр примеров для будущего датасета; веса модели **не дообучаются**.

## Рабочие и домашние проекты
При необходимости укажите `SAYURI_PROJECTS_DIR=C:/Users/USERNAME/Documents/Облако/Sayuri` в своём `.env`.
Разместите внутри две папки: `Рабочие проекты` и `Домашние проекты`. В разделе «Документы» появятся доступные файлы с ограничением области просмотра; файлы не передаются модели без отдельного действия. Отсутствующий путь означает отсутствие доступа. Для любых удалённых устройств необходим защищённый HTTPS-сервер с авторизацией.

## Обновления
`Sayuri.bat` проверяет наличие опубликованного релиза GitHub без принудительной установки. Резервное копирование и атомарная проверенная установка релизов — отдельный этап. Файл `updater.py` не исполняет удалённые скрипты.

## Ограничения прототипа
Для Cloud.ru нужно подтвердить настоящий URL API и ID доступных моделей в кабинете поставщика. Проект не отправляет ключ из браузера/мобильного клиента. Публикация сервера в интернете без HTTPS, защиты входа от перебора, резервного копирования и аудита запрещена. Flutter содержит исходники, а не готовые APK/IPA. GitHub Releases пока только проверяются, не устанавливаются. Реального обучения весов модели нет.

## Дополнительные возможности
- `Sayuri-backup.bat` — архив базы данных и вложений в `data/backups/` или `SAYURI_DATA_DIR/backups/`. Архив не зашифрован: храните его отдельно и защищённо.
- Личный кабинет позволяет выбрать режим речи и уровень нежности, добавить/удалить подтверждённые факты, проверить предложения ИИ-наставника и посмотреть модели Cloud.ru.
- PWA: в мобильном браузере можно установить сайт на домашний экран через меню браузера. Работа с облачной моделью и историей требует доступного сервера.
- Прочитайте [инструкцию подключения Cloud.ru](docs/CLOUD_RU.md) и [архитектуру](docs/ARCHITECTURE.md).
- Загруженные документы и диалоги можно удалить из интерфейса. Старые резервные копии при этом не удаляются автоматически.

## №01 Саюри и №02 наставник
- **№01 — Саюри:** отдельный чат помощницы, её собственная память и личность. Пока генерация ответов использует указанную в `CLOUD_RU_MODEL` облачную модель (не локальную); собственную обученную модель ещё предстоит разработать.
- **№02 — DeepSeek‑V4.1‑Flash:** отдельный чат с ИИ-наставником через `CLOUD_RU_TEACHER_MODEL`. Не подменяйте модель V4.1 на V4 без явного решения владельца; её точный ID необходимо получить из доступных моделей вашего аккаунта Cloud.ru.
- После обмена сообщениями с наставником Sayuri автоматически **наблюдает** разговор: отдельный запрос извлекает кандидатов для долговременной памяти, которые нужно одобрить в личном кабинете. Можно отключить отдельные запросы через `SAYURI_AUTO_OBSERVE=0`.
- История наставника не включается в личную переписку Sayuri, а неподтверждённые знания не сохраняются в её постоянной памяти. Обучение весов ИИ пока не реализовано.

## Единый чат (обновление интерфейса)
Веб-интерфейс и исходники Flutter показывают **один общий чат**. Сообщения пользователя обрабатывает модель наставника из `CLOUD_RU_TEACHER_MODEL`; Sayuri наблюдает диалог, создаёт кандидаты знаний, а владелец утверждает их в личном кабинете. Две кнопки создания чатов, список и поиск диалогов удалены из пользовательского меню. Существующая история в SQLite **не удаляется**; новые сообщения отправляются в самый ранний чат типа `teacher` либо создаётся такой чат, если его нет. Если после обновления интерфейс старый, перезапустите Sayuri и обновите страницу с очисткой кэша (Ctrl+F5).

Если `GET /api/cloud/models` или `POST /api/learning/analyze/...` отвечает **503**, сначала укажите в приватном `.env` правильные `CLOUD_RU_API_KEY`, `CLOUD_RU_BASE_URL` и точный доступный для аккаунта идентификатор `CLOUD_RU_TEACHER_MODEL`; затем перезапустите `Sayuri.bat`. `CLOUD_RU_MODEL` отдельно понадобится, когда будет включён режим самостоятельных ответов Sayuri.

## Локальный запуск без пароля
- В `.env` оставьте `SAYURI_LOCAL_ACCESS=1` (по умолчанию) и слушайте только `127.0.0.1`. Только сам локальный компьютер может получить краткосрочную сессию владельца. Доступ в мобильное приложение или с других компьютеров **не** становится открытым без пароля.
- На экране запуска больше нет ввода пароля: первой страницей служит **Личный кабинет Саюри**. На боковой панели только «Единый чат», «Личный кабинет ИИ», «Документы».
- **Как обновить локальный проект:** остановите `Sayuri.bat`, в директории git-клона выполните `git pull --ff-only origin main`, затем запустите `Sayuri.bat` заново и нажмите Ctrl+F5. Если у вас ZIP вместо git-клона, скачайте новый ZIP с GitHub и замените только файлы программы, **сохранив** `.env`, `data/` и другие пользовательские данные. `updater.py` только проверяет GitHub Releases; сам код не обновляет.
- Для безопасной удалённой публикации установите `SAYURI_LOCAL_ACCESS=0`, настройте домен/HTTPS, разрешённые хосты и серверную авторизацию; **не публикуйте** режим без пароля в сеть.

## Профиль Sayuri 2.0 и ключ Cloud.ru
- В личном кабинете откройте блок **Cloud.ru не настроен**, вставьте секретный API-ключ и нажмите «Сохранить ключ и настройки». При необходимости сначала сохраните только ключ, затем нажмите «Проверить подключение», чтобы получить список ID доступных моделей. Укажите **точный** ID наставника DeepSeek, доступный вашему аккаунту (версия V4.1 не заменяется на V4 автоматически).
- API-ключ вводится только через локальный веб-сервер `127.0.0.1` и сохраняется **только** в локальном `.env`, исключённом из git. Поле после сохранения очищается. Для удалённого размещения предусмотрите отдельный секрет-менеджер и HTTPS.
- Новая книга личности имеет **55 разделов**, **100 диалогов / 540 сообщений**, **400 реплик / 50 категорий**, **9 глав**, **18 ритуалов**, **60 правил и 60 проверок**. Она является спецификацией: автоматические поручения, голос, анимация и обучение весов модели остаются отдельными задачами. См. [интеграцию Persona 2.0](docs/PERSONA_V2.md).
- Полный JSON при желании можно получить локально командой `.venv/Scripts/python.exe -m server.persona`. Исходник в git разбит на 18 последовательных фрагментов, но на работу ядра это не влияет. Не добавляйте синтетические примеры в реальные чаты.

## Левое меню: проекты и обновления
- **Единый чат** — прямой диалог с наставником; Саюри наблюдает и предлагает память на подтверждение.
- **Рабочие проекты** — просмотр и скачивание файлов из `Документы/Облако/Sayuri/Рабочие проекты`.
- **Домашние проекты** — просмотр и скачивание файлов из `Документы/Облако/Sayuri/Домашние проекты`.
- **Документы** — отдельные файлы, загруженные в Sayuri.
- **Личный кабинет Sayuri** — характер, память, настройки Cloud.ru и **Обновления через GitHub**.

Проектные папки создаются автоматически при первом просмотре, если их ещё нет. На Windows системная папка «Документы» определяется через пользовательские настройки Windows, включая перенаправление в OneDrive. При необходимости можно задать `SAYURI_PROJECTS_DIR` в `.env`. Работа с проектными файлами доступна **только на чтение и скачивание**, без изменения оригиналов и без автоматической отправки их содержимого в Cloud.ru. При существующей базе в `data/` данные остаются там — перенос без подтверждения не выполняется. Для новых установок база хранится внутри `Документы/Облако/Sayuri`, если место не переопределено.

В **Личном кабинете Sayuri** есть **Проверить обновления** и **Обновить с GitHub**. Для ZIP-версии Sayuri скачивает архив официальной ветки GitHub, проверяет содержимое ZIP и подготавливает рядом отдельную папку новой версии. Для Git-клона исходный `origin` должен совпадать с официальным URL, рабочее дерево быть чистым, а обновление должно допускать fast-forward. Перед заменой кода резервируются база и вложения, а локальные изменения кода не перезаписываются. После завершения необходимо вручную перезапустить `Sayuri.bat`. Для ZIP-установок программа сообщает путь к подготовленной новой папке, из которой можно запустить `Sayuri.bat` после закрытия старой версии. Проверка релизов при запуске по-прежнему только сообщает о новых версиях и не меняет код автоматически.


## Исправление запуска: отсутствует OneDrive/Documents (WinError 2/3)
Если Windows возвращает путь `C:/Users/.../OneDrive/Documents`, но папка не существует или не подключена, Sayuri теперь ищет доступную локальную `Documents` или `Документы`, затем создаёт `Облако/Sayuri`. При невозможности создать папку используется резервное размещение `data/` для новых чатов и `data/projects/` для проектов в директории установки. Ранее существовавшая `data/sayuri.sqlite3` остаётся на месте, даже если OneDrive впоследствии появится. Настроенный вручную `SAYURI_DATA_DIR` не меняется без согласия пользователя. Текущее фактическое расположение доступно через `GET /api/projects` в полях `root` и `data_root`.

Для ZIP-версии `Sayuri-main` обновление выполняется вручную: скачайте свежий ZIP, сохраните свою папку `data/` и `.env`, затем замените только программные файлы. **Не удаляйте личные данные.** Если папка `OneDrive/Documents` отсутствует, не нужно создавать внутри OneDrive фиктивную структуру вручную — программа выберет существующую локальную папку.


## Обновления ZIP без Git (основной способ установки)
1. Скачайте последнюю версию Sayuri с GitHub один раз и запустите `Sayuri.bat`.
2. В **Личном кабинете Sayuri** откройте блок «Обновления Sayuri через GitHub» и нажмите **Проверить обновления**. Режим автоматически отображается как `ZIP` без необходимости `git clone`.
3. Нажмите **Скачать ZIP-обновление**. Программа проверяет актуальный SHA ветки `main`, скачивает прикреплённый к этому SHA исходный архив **исключительно с GitHub**, проверяет пути файлов и создаёт резервную копию базы/вложений.
4. Программа готовит новую папку, например `Sayuri-main-new-<SHA>`, **рядом** с рабочей `Sayuri-main`. В неё копируются локальные `.env` и `data/`; если данные хранятся во внешней папке, существующий путь сохраняется в `.env`.
5. **Закройте старую Sayuri**, откройте новую папку, запустите `Sayuri.bat`. Первая загрузка может установить зависимости в новую `.venv`.
6. Убедитесь, что чат, память, проекты и настройки на месте. После проверки предыдущую версию можно вручную архивировать. Никакая текущая рабочая папка и память автоматически не удаляются.

В исходной ZIP-версии номер локальной ревизии может отображаться как «ZIP (неизвестна)»; после первого обновления он фиксируется в локальном маркере, не отправляемом на GitHub. Если подготовленная папка уже существует, кабинет покажет её путь. Не открывайте обе версии одновременно для записи в одну и ту же базу. GitHub скачивается через HTTPS; `CLOUD_RU_API_KEY` никогда не отправляется в GitHub и не добавляется в исходный архив.

**Ограничение:** ZIP-обновление подготавливается рядом с предыдущей установкой, а не заменяет её автоматически во время работы. Это защищает живой SQLite и позволяет вернуться к прежней папке при неудачном обновлении. Автоматической проверки криптографической подписи релиза и обновления мобильных сборок пока нет.


## Интерфейс 2.1: кабинет наверху, обновления внизу
Новая левая панель: верхняя отдельная кнопка **«Личный кабинет Sayuri»**, затем разделитель, меню **«Единый чат»**, **«Рабочие проекты»**, **«Документы / Облако / Sayuri»**, **«Домашние проекты»**, свободный промежуток и закреплённая нижняя кнопка **«Обновление проекта»**. На небольших экранах меню открывается кнопкой ☰.

**Личный кабинет** содержит пять разделов: 01. «Живой характер», 02. «Навыки», 03. «Опыт и дневник», 04. «Библиотека знаний» и 05. «История развития». Приветствия и художественная мимика переключаются по взаимодействию; плавное движение портрета сделано CSS. Возможность выключения движения соблюдает системную настройку reduced motion. Озвучивание — **не синтез речи облачной модели**, а доступная на устройстве функция браузера, включаемая вручную. Полноценные выражения лица/Live2D и обученный персональный голос ещё не реализованы. Нет притворных эмоций или неподтверждённых процентов навыков: опыт и история формируются из фактических записей SQLite, история библиотеки из подтверждённой памяти и загруженных источников.

**Облачное хранилище** — локальный менеджер файлов, работающий по принципу Яндекс Диска/Облака Mail.ru, но **без синхронизации с ними или регистрации у провайдера**. Управляемое пространство находится в `Документы/Облако/Sayuri/Мои файлы` (при недоступной системной папке используется резервная директория). Доступны вложенные папки, поиск по именам, загрузка файлов до 25 МБ, скачивание, переименование и удаление. Удаление непустой папки не допускается, доступ по символическим ссылкам и выход за пределы «Мои файлы» запрещены. Разделы «Рабочие проекты» и «Домашние проекты» остаются отдельными областями только для чтения.

## Sayuri 3 — обновлённый единый дизайн
Предыдущая версия одновременно содержала три конфликтующих блока встроенных стилей. Вместо их последовательного переопределения в **Sayuri 3** используется **единый** `web/theme.css`. Он задаёт спокойную палитру тёмных графитовых поверхностей, мягкие лилово-розовые акценты, типографику, поля и адаптивную сетку. Профиль Саюри вверху, навигация и компактная диагностика слева, обновления внизу; в кабинете на первом плане характер, навыки и знания, а расширенные опции свернуты в один раздел. Чат с наставником и работа с документами сохраняют прежние API и историю. На телефоне нет горизонтальной прокрутки, меню закрывается по Escape/затемнению, соблюдён `prefers-reduced-motion`.

Проверка внешнего вида: `tests/ui_smoke.py` открывает реальный сайт в Chromium на 360, 390, 768, 1024 и 1440 px, проверяет стили, доступность и компоновку, а результаты визуального прогона публикуются на вкладке Actions в артефакте `sayuri-ui-previews`. Скриншоты создаются из временной тестовой базы без пользовательских секретов. Откройте последнюю успешную задачу **Sayuri tests** на GitHub. После скачивания новой ZIP-версии обновление браузера с Ctrl+F5 загружает `/static/theme.css?v=3.0.0`.

## Постоянная Саюри — основной релиз (BEYOND 2.0)
Функция **входит в основную ветку `main`**. При запуске сайта в правом нижнем углу появляется компактная Саюри. Она остаётся доступной при переходах по SPA; правый клик открывает меню действий, двойной — единый чат, перетаскивание — перемещение. С компьютера доступно Ctrl+колесо для масштаба. Долгое касание на телефоне открывает меню.

Чтобы установить два оригинальных изображения, откройте **Личный кабинет → 01. Живой характер Саюри → Быстрая установка образа Саюри** и загрузите комплект `Sayuri-BEYOND-2-Avatars.zip`, содержащий `portrait.png` и `full.png`. После подтверждения она сразу переключится в полноразмерный режим. Это локальный файл пользователя, поэтому **публичный GitHub не содержит авторских исходников**. Можно загружать изображения по отдельности. Положение, режим и тихий режим сохраняются в локальной SQLite; файлы — в `data/appearance`.

Для обычной ZIP-установки обновляйте с `https://github.com/Aspksa/Sayuri/archive/refs/heads/main.zip` с резервной копией прежних `.env` и `data`. Не удаляйте старую папку до проверки чатов и памяти. Остальные фазы BEYOND 2.0 (полноценная обработка документов, граф знаний, надёжная очередь, тестирование навыков, планировщик) не следует считать реализованными только по наличию спецификации.

## Sayuri Core 3.0 · Memory 3.0 (Project 4.8.0)

В проекте **4.8.0** начат отдельный слой **Sayuri Core 3.0**. Первый модуль ядра — **Memory 3.0**. Persona остаётся версии **2.0.0**: версия ядра и версия характера теперь учитываются отдельно.

Memory 3.0 делит записи на личные, проектные, рабочие и временные. Для каждой записи сохраняются тип, приоритет, confidence, источник, ссылка на источник, даты обновления и фактического использования; временная память поддерживает TTL и после истечения архивируется, а не исчезает без следа.

Проектная память привязана к стабильному `project_id` рабочих и домашних проектов. При работе с одним проектом память другого проекта не включается в контекст. Отдельный DeepSeek-наставник не получает личную или проектную память Sayuri: предложенные наставником факты становятся памятью только после подтверждения владельца.

Существующая таблица памяти мигрируется автоматически и без удаления старых записей. Подробный контракт: `docs/SAYURI_MEMORY_3.md`.
