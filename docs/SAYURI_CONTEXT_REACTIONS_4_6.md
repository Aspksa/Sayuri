# SAYURI BEYOND Context Reactions 4.6

## Назначение

Context Reactions связывает визуальное поведение SAYURI BEYOND с реальными объектами и событиями локального интерфейса Sayuri.

Движок различает четыре основных типа контекста:

- документ;
- проект;
- задача;
- уведомление.

## Точная привязка

Элементы интерфейса могут содержать стабильные атрибуты:

- data-sayuri-entity-type;
- data-sayuri-entity-id;
- data-sayuri-module.

Для файлов и проектов используется стабильный идентификатор или полный относительный путь. Движок не ищет объект по видимому тексту карточки, поэтому одинаковые имена файлов не должны приводить к неверной привязке.

Если объект с подходящим идентификатором видим, реакция считается точной. Саюри выбирает позицию рядом с объектом и передаёт его прямоугольник в Spatial Awareness как временно защищённую зону, поэтому персонаж не должен закрывать сам объект.

## Fallback

Если точная карточка отсутствует или скрыта, Context Reactions не имитирует точную привязку.

Используются видимые области:

- документы: файловая область или активный экран;
- проекты: браузер рабочего/домашнего проекта или активная область;
- задачи: видимый runtime/status-блок или активный экран;
- уведомления: само уведомление, статус обновления или активный экран.

В диагностике такая реакция имеет exact=false.

## Реакции

| Контекст | Состояние | Поведение |
|---|---|---|
| документ | reading | подходит к карточке, если она видима |
| проект | thinking | подходит к области проекта |
| задача выполняется | working | использует реальный runtime/status |
| задача завершена | happy | показывает подтверждение завершения |
| ошибка задачи | attention | привлекает внимание |
| уведомление | attention | подходит к уведомлению или его статусной области |
| память обновлена | happy | показывает краткую реакцию |
| противоречие | attention | сообщает, что нужна проверка |

## Источники событий

Контекст поступает через локальные события sayuri:context и sayuri:runtime. В 4.6 размечены карточки локального файлового хранилища, файлов рабочих/домашних проектов, документов библиотеки и уведомления подготовленного обновления.

Runtime-переходы executing, completed и attention преобразуются в контекст задачи даже тогда, когда отдельной карточки задачи в интерфейсе нет.

## Диагностика

Окно настроек показывает блок Context Reaction с текущим типом реакции и пояснением.

Для UI-тестов доступен объект window.SayuriReactions:

- getSnapshot() — последняя реакция;
- react(detail) — тестовый вызов реакции только для поддерживаемого типа события.

## Ограничения

Context Reactions не читает произвольный текст экрана, документы или сторонние приложения. Точная привязка разрешена только к размеченным DOM-элементам локального интерфейса. Если такой элемент отсутствует, используется явно обозначенный fallback.
