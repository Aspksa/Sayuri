# Sayuri Knowledge Engine 3.1

Knowledge Engine 3.1 — второй слой Sayuri Core после Memory 3.0. Он не заменяет память: Memory хранит подтверждённые записи, а Knowledge 3.1 индексирует их, связывает, показывает происхождение и помогает находить противоречия.

## Версии

- Project / UI: **4.9.0**
- Sayuri Core: **3.1.0**
- Knowledge: **3.1.0**
- Memory: **3.0.0**
- Persona: **2.0.0**

Версии хранятся в `web/build.json` и возвращаются через `/api/build/info`. `/api/health` также сообщает версии Core, Memory и Knowledge.

## Что входит в Knowledge 3.1

### Локальный поиск по смысловой близости

Knowledge 3.1 строит локальный индекс подтверждённых активных записей памяти. Для каждой записи вычисляется детерминированный вектор признаков из нормализованных слов и символьных триграмм.

Поиск учитывает:

- совпадение слов;
- похожие формы слов через символьные фрагменты;
- общий коэффициент близости;
- явные связи графа;
- приоритет памяти.

Индекс хранится локально в SQLite (`knowledge_index`). Текст памяти для построения индекса во внешнюю модель не отправляется.

Важно: это **локальный similarity-index**, а не нейронная embedding-модель. Он даёт более содержательный поиск, чем простое `LIKE`, но не должен считаться полноценным языковым пониманием или внешней векторной моделью.

## Граф знаний

Таблица `knowledge_links` хранит явные связи между двумя записями Memory 3.0.

Поддерживаются типы:

- `related` — связано с;
- `supports` — подтверждает;
- `contradicts` — противоречит;
- `derived_from` — получено из;
- `updates` — обновляет.

Связь имеет confidence и необязательный комментарий.

Во время поиска близкое знание может усилить связанные с ним записи, поэтому граф участвует в ранжировании.

## Источники

Knowledge 3.1 не теряет происхождение записи.

В первом релизе источники формируются из полей Memory 3.0:

- `user_confirmed` — подтверждено владельцем;
- `teacher_reviewed` — предложено наставником и затем подтверждено владельцем;
- `source_ref` — ссылка на конкретный чат, документ или другой источник, если она сохранена;
- другие типы источников сохраняются без подмены.

Источник и confidence показываются отдельно. Высокая похожесть текста не повышает доверие к источнику автоматически.

## Противоречия

Knowledge 3.1 формирует **кандидаты противоречий**, а не объявляет одну запись истинной, а другую ложной.

Кандидат возникает, если:

- пользователь явно создал связь `contradicts`;
- два очень похожих утверждения имеют разную полярность (например, «может» / «не может»);
- два похожих утверждения содержат разные числовые значения.

Каждый кандидат получает стабильный `conflict_key`.

Статусы:

- `pending` — требует проверки;
- `resolved` — проверено;
- `ignored` — не считать конфликтом.

Решение пользователя сохраняется в `knowledge_conflict_reviews`.

Sayuri при формировании ответа получает предупреждение о релевантных нерешённых противоречиях и инструкцию не выбирать сторону без проверки.

## Проектный контекст

В общем центре Knowledge 3.1 можно искать по всем проектам.

Если выбран конкретный проект, локальный поиск и список конфликтов ограничиваются:

- общей личной памятью;
- рабочей памятью;
- временной памятью;
- проектной памятью только текущего `project_id`.

При формировании ответа Sayuri проектная изоляция остаётся обязательной: память другого проекта в контекст ответа не попадает.

## API

- `GET /api/knowledge/summary`
- `GET /api/knowledge/search?q=...`
- `GET /api/knowledge/sources`
- `GET /api/knowledge/links`
- `POST /api/knowledge/links`
- `DELETE /api/knowledge/links/{id}`
- `GET /api/knowledge/conflicts`
- `PUT /api/knowledge/conflicts/{conflict_key}`

Все маршруты требуют локальной авторизации владельца.

## Интерфейс

В Личном кабинете блок «Знания 3.1» показывает:

- число индексированных записей;
- число явных связей;
- число источников;
- число найденных конфликтов и количество нерешённых;
- локальный поиск;
- происхождение знаний;
- кандидаты противоречий с ручной проверкой;
- редактор связей между записями памяти.

## Что пока не входит

Knowledge 3.1 не индексирует содержимое загруженных документов автоматически. Документ появляется в знаниях только после будущего этапа Study / Document Knowledge, который должен извлекать данные с привязкой к цитате и версии файла.

Также в 3.1 нет внешней embedding-модели, полноценного онтологического графа сущностей и автоматического разрешения противоречий. Эти ограничения намеренные: система не должна притворяться, что доказала факт только на основании текстовой похожести.
