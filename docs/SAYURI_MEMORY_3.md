# Sayuri Memory 3.0

Memory 3.0 — новый слой памяти Sayuri Core. Он заменяет прежнюю плоскую модель `scope + text` на типизированную, проектно-зависимую память с происхождением, приоритетом и сроком жизни.

## Версии

- Project / UI: **4.8.0**
- Sayuri Core: **3.0.0**
- Memory: **3.0.0**
- Persona: **2.0.0**

Версии Core и Memory хранятся в `web/build.json` и возвращаются через `/api/build/info` и `/api/health`.

## Области памяти

Memory 3.0 поддерживает четыре независимые области:

- `personal` — устойчивые личные предпочтения, подтверждённые факты и решения владельца;
- `project` — информация, действующая только внутри конкретного проекта;
- `working` — текущие рабочие правила и контекст, доступные Sayuri при выполнении задач;
- `temporary` — краткосрочная память с TTL, которая автоматически архивируется после истечения срока.

Проектная запись обязательно содержит `project_id`.

## Типы записей

- `fact`
- `preference`
- `decision`
- `rule`
- `correction`
- `note`

Каждая запись также содержит приоритет 1–5, confidence 0–1, источник, необязательную ссылку на источник, даты создания/изменения, статус и отметку последнего фактического использования.

## Контекст проекта

Рабочие и домашние проекты получают стабильный идентификатор памяти:

- `work:__root__` / `home:__root__` для корня;
- `work:<верхняя папка>` / `home:<верхняя папка>` для конкретного проекта.

Вложенные директории одного верхнеуровневого проекта используют тот же проектный контекст. Это не привязывает память к абсолютному пути Windows.

При формировании контекста Sayuri выбираются:

- личная память;
- рабочая память;
- проектная память только для текущего `project_id`;
- глобальная временная память и временная память текущего проекта.

Память другого проекта не подмешивается.

## Временная память

Для `temporary` задаётся TTL. Если TTL не указан через API, используется 24 часа. Истёкшая запись не удаляется молча: она переводится в `archived`, чтобы история оставалась проверяемой.

## Источники и доверие

Пользовательские записи сохраняются с `source=user_confirmed` и confidence 1.0 по умолчанию.

Кандидат, предложенный ИИ-наставником и затем явно подтверждённый владельцем, сохраняется через Memory 3.0 с:

- `source=teacher_reviewed`;
- `source_ref=chat:<id>`;
- confidence 0.9.

Предложение наставника само по себе памятью не становится.

## Приватность наставника

Отдельный DeepSeek-наставник не получает личную или проектную Memory 3.0. В teacher-chat память Sayuri не подмешивается и не помечается как использованная. Это сохраняет границу между локальной памятью Sayuri и внешней моделью.

## Миграция старой памяти

При запуске Sayuri автоматически проверяет существующую таблицу `memories` и добавляет недостающие поля через `ALTER TABLE`.

Старые записи:

- не удаляются;
- сохраняют исходный текст, source и created;
- получают `memory_type=fact`;
- priority 3;
- confidence 1.0;
- status `active`;
- updated = исходному created.

Ручной перенос базы не требуется.

## API

Основные маршруты:

- `GET /api/memory` — список с фильтрами scope/project/status/search;
- `GET /api/memory/summary` — агрегированная статистика;
- `GET /api/memory/context` — память, доступная для заданного проекта;
- `POST /api/memory` — создать запись;
- `PUT /api/memory/{id}` — изменить запись;
- `POST /api/memory/{id}/archive` — архивировать;
- `DELETE /api/memory/{id}` — окончательно удалить.

## Интерфейс

В Личном кабинете Memory 3.0 вынесена в основной раздел. Можно выбрать область, тип, приоритет, проект и TTL, фильтровать записи, искать, архивировать и удалять.

В экранах Рабочих/Домашних проектов отображается текущий `project_id` и кнопка перехода прямо к памяти этого проекта.

## Ограничения первого релиза

Memory 3.0 пока не является семантическим vector store и не строит граф знаний. Отбор контекста в 3.0 основан на области, проекте, приоритете, confidence и времени. Семантическое извлечение, связи и разрешение противоречий относятся к следующему этапу Knowledge/Memory Engine.
