# Sayuri UI 4.0 — отдельный SAYURI BEYOND и понятный личный кабинет

**Основная ветка `main` · октябрь 2026.**

## Разделение функций

**Личный кабинет Sayuri** — верхняя карточка слева, центральный экран с двумя разными отметками:

- **Личность — SAYURI 2.0** (профиль характера из 18 частей).
- **Интерфейс — 4.0.0** (версия веб-оформления и системы разделов).

В кабинете остаются проверенные **навыки**, **опыт**, **библиотека знаний**, **история развития** и **Cloud.ru**. Для часто используемых действий добавлены большие карточки, дополнительные настройки сворачиваются.

**SAYURI BEYOND** — отдельный экран приложения, открывается из отдельной кнопки слева либо из личного кабинета. Здесь: художественное приветствие, браузерная озвучка по запросу, настройки движения, образ персонажа, импорт `portrait.png` / `full.png`, ZIP-комплект из двух PNG, режимы отображения, видимость и восстановление положения. Это отдельная **страница внутри сайта**, не второе окно Windows и не фоновая программа поверх ОС.

## Главное меню

- Верхняя карточка: Личный кабинет Sayuri.
- **SAYURI BEYOND** — отдельный пункт.
- Единый чат.
- Рабочие проекты.
- Документы / Облако / Sayuri.
- Домашние проекты.
- Снизу постоянно: **Обновление проекта**.

Диагностика работы сервера остаётся на левой панели отдельно от меню.

## Почему после ZIP-обновления мог оставаться прежний дизайн

Пользователь скачивает `Sayuri-main.zip` и запускает BAT из распакованной папки, а не работает с Git-клоном. Предыдущее меню лишь показывало SHA с GitHub и пыталось обновить код, **подготавливая новый ZIP в соседней папке**. Уже запущенный сервер на `127.0.0.1:8765` не перезапускается от изменения исходных файлов в другой папке. Поэтому «обновление завершено» не означало «новый интерфейс запущен».

Теперь раздел «Обновление проекта» выводит:
1. **Версию запущенного интерфейса** (из `web/build.json` на сервере).
2. **Путь к реально запущенной папке**, независимо от имени скачанного архива (авторизованный `GET /api/build/info`).
3. **Ревизию GitHub**, отдельную кнопку проверки.
4. После ZIP-обновления — **точный путь новой папки** и явное пояснение: старый BAT необходимо закрыть, а новый запустить из созданной папки.
5. Пошаговый порядок закрытия старого сервера, проверки пути и Ctrl+F5.

`web/build.json` отражает номер интерфейса, а не признак обучения модели. Для обычного ZIP без `.sayuri-source.json` SHA локального исходного архива **неизвестен**, поэтому сравнение с GitHub не подтверждает точно, что версия устарела.

Чтобы самостоятельно установить свежую сборку: [Скачать `main.zip`](https://github.com/Aspksa/Sayuri/archive/refs/heads/main.zip). Сохраните `.env`, `data/` и внешние папки с документами, если они используются. Никогда не удаляйте последнюю рабочую копию, не проверив перенос SQLite, памяти и образов.

## Проверки

`tests/ui_smoke.py` проверяет рендер пяти ширин экрана в Chromium и отдельную работу интерфейсов; `tests/test_ui_version.py` защищает от подмены версии и неавторизованного чтения пути. `python -m pytest -q`, компиляция и проверка JS также запускаются в CI.

Новый код не означает автоматического изменения содержимого уже запущенной локальной ZIP-папки. **GitHub не имеет прямого доступа к Windows владельца.**
