# Установка и восстановление Sayuri из ZIP на Windows

**Для пользователя, который скачивает ZIP с GitHub и запускает `Sayuri.bat`.** Не требуется `git clone`.

## Проверка — действительно ли открыта новая сборка

1. В проводнике откройте папку, из которой запускается `Sayuri.bat`, обычно `%USERPROFILE%\OneDrive\Рабочий стол\Sayuri-main`. Убедитесь, что именно в этой папке есть `web\index.html`, `web\companion.js`, `web\companion.css` и `server\companion.py`.
2. Откройте `web\index.html` через **Блокнот**. Ctrl+F → `Интерфейс 3.2`. Наличие этой строки подтверждает, что в папке находится актуальная **разметка**; отсутствие означает старый ZIP или распаковку «папка внутри папки».
3. **Закройте все** старые окна `Sayuri.bat` и `python.exe`/терминала Sayuri. Если сервер на порту 8765 уже запущен из другой папки, новый BAT может открыть **старый сервер**. Не завершайте посторонние процессы Python без проверки.
4. Запустите `Sayuri.bat` из нужной папки. Адрес: `http://127.0.0.1:8765`. В браузере нажмите **Ctrl+F5** (при необходимости попробуйте приватное окно).
5. В **Личном кабинете** должны быть **обе** надписи: `ЛИЧНЫЙ КАБИНЕТ · SAYURI 2.0` (**версия характера**) и `Интерфейс 3.2 · загрузка образа` (**версия интерфейса**).
6. Под приветствием нажмите **«Установить образ ↓»**. Это приводит к **«01. Живой характер Саюри» → «Установка внешности Саюри» → «↑ Выбрать ZIP с образами»**.
7. Используйте комплект с **`portrait.png` и `full.png`** в корне ZIP, либо загрузите два PNG отдельно. После корректного импорта персонаж перейдёт в полноразмерный режим. Кнопка **«Вернуть Саюри справа»** восстанавливает положение, если фигура потерялась за панелями.

Если Ctrl+F в `index.html` нашёл `Интерфейс 3.2`, но страница всё ещё старая, вероятнее всего браузер подключён к **другому запущенному серверу**. Тот факт, что папка называется `Sayuri-main`, сам по себе ничего не доказывает.

## Если нужно скачать свежую версию

Ссылка на основную ветку:  
**https://github.com/Aspksa/Sayuri/archive/refs/heads/main.zip**

1. Сначала выйдите из Sayuri. **Не удаляйте** старую папку, пока не подтверждено сохранение данных.
2. Создайте отдельную папку для свежей версии и распакуйте ZIP.
3. Скопируйте личный `.env` (если существует) и `data/` из прежней копии в новую **без перезаписи новыми файлами-заглушками**. Проверьте, не установлен ли `SAYURI_DATA_DIR`: реальная база может быть **внешней**.
4. Пользовательские проекты могут находиться в `Документы\Облако\Sayuri`, а не в `data/`. Не удаляйте и не перемещайте их без резервной копии.
5. Запустите только новую версию `Sayuri.bat`, дождитесь зависимостей. Откройте новый кабинет, проверьте чат, память, настройки Cloud.ru и изображения.
6. Лишь после проверки можно архивировать прежнюю установку.

**Не копируйте** чужой `.env`, токены или данные в публичный GitHub. Не запускайте одновременно старую и новую версию с общей SQLite БД.

## Автоматическая подготовка ZIP-обновлений

В кабинете внизу меню: **«Обновление проекта» → «Проверить обновления» → «Скачать ZIP-обновление»**. Новая версия создаётся **в соседней папке**, например `Sayuri-main-new-xxxxxxxxxxxx`; не перезаписывает работающие файлы. Из этой папки требуется отдельно запустить `Sayuri.bat`. Для ручного ZIP-обновления действуют предыдущие шаги по защите данных.

## Если старая папка уже удалена

- Проверьте **Корзину Windows**. Если в ней сохранились `.env`, `data/`, `sayuri.sqlite3` или `appearance/`, восстановите их в отдельную безопасную папку перед переносом.
- Проверьте, не существовали ли данные **вне установки**, например в действительном `Документы\Облако\Sayuri` или директории из `SAYURI_DATA_DIR`.
- Даже если старый ZIP удалён, история могла остаться во внешнем SQLite. **Не** создавайте вторую пустую базу вместо существующей.
- Если файлы данных действительно удалены и резервной копии нет, GitHub **не содержит** переписок, личных воспоминаний, ключей Cloud.ru и приватного облика: восстановить их из исходного кода нельзя.
- При ошибках `WinError 2`/`WinError 3` проверьте доступность Documents/OneDrive. `server/paths.py` использует системное расположение папки и резервный путь; явно прописанные `SAYURI_DATA_DIR`/`SAYURI_PROJECTS_DIR` нужно исправить вручную, если пути исчезли.

## Данные, которые нельзя путать

| Тип | Где искать |
| --- | --- |
| Код программы | `Sayuri-main\` |
| Ключи Cloud.ru, конфигурация | `.env` около BAT (либо специально заданная конфигурация) |
| Чат, подтверждённые знания и настройки | `sayuri.sqlite3` под выбранным корнем данных |
| PNG персонажа | `appearance/` под тем же корнем данных |
| Управляемые документы | `Документы\Облако\Sayuri\Мои файлы` либо резервная папка |
| Рабочие и домашние проекты | `Документы\Облако\Sayuri` либо `SAYURI_PROJECTS_DIR` |
| Папка ZIP-обновления | Рядом с текущей `Sayuri-main` |

В разных установках реальный корень данных определяется `server/paths.py`: ранее созданная локальная база имеет приоритет, после неё существующая база в облачной папке; явный `SAYURI_DATA_DIR` имеет наивысший приоритет. Не полагайтесь только на имя папки.

## Как получить данные для диагностики

Сообщите **только** версию строки из `web\index.html`, путь до запуска `Sayuri.bat`, текст ошибки из терминала **без секретов** и видимые элементы кабинета. Никогда не публикуйте содержимое `.env`, токены и закрытые документы.
